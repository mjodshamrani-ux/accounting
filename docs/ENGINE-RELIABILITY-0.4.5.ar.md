# تدقيق المحرك 0.4.5

النطاق هو كشف المورد مقابل تقرير الحسابات الدائنة. المعالجة محلية، ولا توجد خدمة AI أو OCR سحابية جديدة. إصدار المحرك `0.3.10-experimental`؛ الجلسات القديمة تحتاج إعادة معالجة لأن قواعد قبول الأدلة تغيّرت.

## كيف تحقّقنا

1. حُفظت نسخة 0.4.4 قبل التعديل، ونجحت اختبارات المشروع القائمة **463/463** وTypeScript. كشف الاختبار المستقل عيوبًا رغم نجاحها.
2. أُثبتت أخطاء القراءة والمعنى والنطاق باختبارات فاشلة ثم أُصلحت. أُضيفت حالات قريبة ومضادة تمنع التوسع غير الآمن في القبول.
3. بدأ المولّد بـ40 حالة ذات إجابات محسوبة صراحةً، ثم أُنتج ملفان فعليان لكل حالة ضمن 5,000 حالة. استُخدمت المصادر الفعلية في القراءة والمقارنة والتصدير؛ ليست استدعاءات لدالة المطابقة بصفوف مجهزة فقط.
4. لا يستورد المولّد أو مدقق Excel المستقل دوال المحرك لحساب الإجابة. يبدأ المولّد بأحداث اقتصادية ثم رؤيتي المورد والشركة. المعرّفات الاقتصادية لا تدخل الملفات أو المحرك. العلاقة المخفية لا تمنح إذن المطابقة.
5. التقسيم **3,514 تطوير +992 تحقق +494 حجز نهائي**. عائلات التنسيق منفصلة بين الأقسام؛ حُجز منتج OOXML مستقل وتركيبات إضافية للفترة والافتتاحي وتجزئة النص. ليس الفصل بتغيير seed وحده، لكنه يظل اختبارًا داخليًا صناعيًا، وليس تحققًا ميدانيًا مستقلًا.
6. جُمّد المحرك قبل فتح الحجز النهائي، مع حفظ بصمات SHA-256. بعد التشغيل الأول أُضيف للمدقق نفسه شرط إضافي يمنع إعلان قابلية تسوية الأرصدة دون دليل وجسر، استنادًا إلى طفرة في حالة تطوير. لم تتغير قواعد المحرك أو المولّد، وأُعيد التقييم قبل/بعد بالمدقق نفسه. الحجز المعاد تشغيله لا يوصف بأنه حجز جديد غير معروف.

النسخة النهائية للمولّد `tarasuf-independent-1.0.1` وseed افتراضي `4564764`. صُححت قبل التقييم النهائي ثلاثة عيوب في fixtures: حالة غموض الفاصل كانت تفترض قيمة مخفية لا يمكن استنتاجها، وتنسيق أرصدة PDF لم يكن متسقًا مع تنسيق حركاته، وروابط حدث الدفع المجزأ في الإجابة المرجعية. حُفظت النسخة السابقة وسجلاتها؛ لم تُنسب هذه التصحيحات إلى نجاح المحرك.

## ما تغير ولماذا

| المشكلة المثبتة | الإصلاح العام | الاختبار الحارس |
|---|---|---|
| XML Excel مكرر أو ناقص يُسقط صفوفًا وأوراقًا | التحقق من وحدانية البنية والإحداثيات والروابط قبل ExcelJS | `reliability-import-045` |
| خلية تحتوي قيمتين متعارضتين قد تنتج 100999 بدل 100 | رفض حمولة الخلية المتعارضة أو المكررة | `reliability-import-045` |
| إعادة تعريف نظام التاريخ أو التنسيق تغيّر التاريخ والأصفار البادئة | رفض تعريفات المصنف المتعارضة وحفظ المرجع كنص | `reliability-import-045` |
| تطابق أرقام بين موردين أو حسابين مختلفين | فحص الهوية بحسب الدور، وإيقاف الحساب العام المتعارض بدل افتراض تساوي الأدوار | `reliability-core-045` و`reliability-scope-045` |
| مقارنة أصل مبلغ المستند بالمتبقي أو بالرصيد الجاري | عنوان الحقل ونوع التقرير يقيّدان التعيين اليدوي والآلي | `reliability-core-045` |
| تقرير أعمار ديون يُعامل ككشف حركات | عنوان التقرير الصريح يمنع اعتماد هذا المسار | `reliability-scope-045` |
| لقطة بنود مفتوحة حالية أو فترة تالفة تثبت رصيدًا تاريخيًا | فحص تاريخ اللقطة والفترة والتعارض قبل بناء الجسر | `reliability-core-045` |
| العملة المعلنة تخالف العملة المختارة | لا تُنسب الحركة الأجنبية إلى عملة النطاق؛ يبقى الأصل والخطأ للمراجعة | `reliability-scope-045` |
| بيانات رأس PDF والتذييل تدخل كحركات تالفة | فصل ضيق للبيانات التعريفية والأرصدة والتذييلات المثبتة مع تسجيل الاستبعاد | `reliability-pdf-045` |
| تاريخ PDF في غير العمود الأول، أو ترويسات صفحة ثانية | تحديد التاريخ من الرأس الصريح ودعم الترويسات المتكررة دون حذف حركة تحمل مرجعًا ومبلغًا | `reliability-pdf-045` |
| مرجع فاتورة رقمي صريح يُحال دائمًا للمراجعة | قبول 1:1 فقط عند رقم مستند صريح ونوع فاتورة/إشعار دائن مثبت وبقية الأدلة سليمة؛ لا مساواة بين 00123 و123 | `reliability-core-045` |
| فترة موثقة بلا حركات عند القطع لا تقبل المقارنة | السماح بها فقط مع فترة وأرصدة ظاهرة متسقة وغياب أخطاء القراءة | `reliability-scope-045` |
| بطء Excel يزداد تربيعيًا | حساب أبعاد الورقة مرة واحدة بدل مسح جميع الصفوف عند كل خلية | قياس الأداء قبل/بعد واختبارات القراءة |
| قالب الأعمدة الاختياري يحتفظ بدليل اتجاه مشتق من المصدر | عدم حفظ `directionEvidence` مع القالب الجديد | مراجعة المصدر وحدود التخزين |

لا يُستخدم المبلغ وحده أو قرب التاريخ أو تشابه الوصف أو FIFO لاعتماد المطابقة. تكرار المرجع والتعارض يظلان للمراجعة. وصف يبدأ بنوع مستند متعارض يمنع الاعتماد، لكنه لا يصبح دليلًا كافيًا لإثبات النوع.

## النتائج وكيف تُقرأ

التفاصيل العددية قبل/بعد موزعة بحسب الفئة والعائلة والسيناريو في [دليل التشغيل الفعلي](../audit/reliability/evidence-0.4.5.json) و[جدول النتائج](../audit/reliability/RESULTS-0.4.5.ar.md).

- نجاح حالة سليمة يعني صحة القراءة والأدلة والقرار والجسر المتاح وملف النتائج. نجاح حالة تالفة يعني توقفًا واضحًا مطابقًا للسبب المتوقع، وليس مطابقة.
- تُفصل المطابقات الفردية المطلوبة عن مجموعات الدفع المسموح بها اختياريًا. بقيت مجموعات الدفع الـ154 في هذه الحزمة للمراجعة؛ لا يُدّعى إنجاز تخصيصها تلقائيًا.
- يُقاس اختيار الأعمدة الآلي منفصلًا عن تأكيد النطاق واتجاه الإشارة. يحاكي التقييم تأكيد المحاسب للمعلومات الظاهرة وتفسير التاريخ/الفاصل عند الغموض. لا يُحتسب هذا مسارًا بلا تأكيدات.
- PDF النصي يبقى محتاجًا مراجعة الاستخراج. عدد الحالات المجتازة ليس نسبة دقة تسويقية، والتوزيع الصناعي لا يمثل السوق.
- لا تجمع قيمة المطابقات الخاطئة بين العملات. القيم في التقرير بوحدات العملة الصغرى لكل عملة على حدة، ومن جانب المورد فقط.

## فحص المخرجات والاختبارات نفسها

مدقق التصدير يقرأ ZIP وXML باستخدام JSZip وSAX ويحسب بـBigInt دون ExcelJS أو محرك المحاسبة. يتحقق من المراجع والتواريخ والأصفار والإشارات، مجموعات المطابقة مقابل عدد الصفوف، اكتمال أثر الجسر، العرض العربي، وأرصدة الملخص. يعيد حساب صيغ Excel المسموح بها ويقارنها بالقيم المخزنة؛ تغيير الصيغة مع إبقاء cache صحيحًا لا يمر. النصوص لا تصبح صيغًا أو روابط خارجية.

طفرات مدقق التصدير تغيّر القيمة والإشارة والمرجع والعداد والصيغة وغيرها. طفرات المقيم تغيّر إجمالي المصدر، أو تعكس طرفي فاتورتين متساويتي المبلغ، أو تعلن تسوية أرصدة دون دليل، أو تحيل كل شيء للمراجعة. الانهيار البرمجي والإلغاء لا يُحتسبان رفضًا ناجحًا. طفرات الإنتاج المعزولة تختبر تعطيل حواجز الهوية والعملة والتكرار وAI والقراءة والتصدير؛ الخطأ النحوي لا يُحتسب كشفًا محاسبيًا.

يبقى المصدر محفوظًا مع قيمته الأصلية ورقمه وورقته وصفه وبصمته. مصدر PDF موثق بالصفحة وصف الاستخراج؛ لا ندّعي إحداثيات نص دقيقة في التصدير لا يحتفظ بها القارئ النهائي.

## الأداء والحدود

قياس محلي على Apple M5 بذاكرة16GiB وNode24.19.0، بعملية منفصلة لكل حجم، ملفان فعليان لكل تجربة. هذه أزمنة جهاز واحد وليست وعدًا بأداء كل متصفح.

| صفوف كل طرف | الصيغة | قبل الإصلاح | بعد الإصلاح | ما قيس |
|---|---|---|---|---|
| 5,000 | XLSX | 13.097 ثانية | 6.655 ثانية | توليد وقراءة ومقارنة وتصدير وإعادة فتح |
| 20,000 | XLSX | لم يكتمل خلال60 ثانية | 3.575 ثانية | توليد وقراءة ومقارنة دون تصدير |
| 20,000 | CSV | 0.777 ثانية | 0.932 ثانية | توليد وقراءة ومقارنة دون تصدير |

تذبذب الأزمنة الصغيرة متوقع. بلغت الذاكرة في تجارب التصدير عند5,000 صف قرابة816–891MB بعد الإصلاح؛ لا ندّعي تحسنًا عامًا في الذاكرة. لم يُختبر تصدير20,000 صف أو الأداء على هواتف ضعيفة. إعادة فتح ملفات الأداء تستعمل ExcelJS وهي فحص round trip؛ التدقيق المستقل يأتي من الحزمة الأخرى.

حدود التشغيل الحالية:8MiB للملف،32MiB لفك ZIP،40 ورقة،20,000 صف مع هامش30 صفًا للترويسات،100 عمود ومليون خلية للمصنف. PDFحتى20 صفحة، ومجموعة المطابقة الآلية حتى100 حركة. مهلة العامل45 ثانية؛ الإلغاء أو المهلة لا ينتجان نتيجة مكتملة. اختبارات العامل تتحقق من الرسائل المتأخرة وتعطل العامل وتداخل الطلبات والتعافي بعدها.

## حدود الدعم

| المسار | ما تدعمه النسخة |
|---|---|
| XLSX/CSV بحركات واضحة ضمن نطاق واحد | استخراج ومطابقة فردية محافظة؛ تأكيد محدود عند غموض الصيغة أو الإشارة أو النطاق |
| PDF نصي بجدول قابل للاستخراج | اقتراح أعمدة وقراءة ومقارنة بعد مراجعة الاستخراج؛ القالب غير الواضح لا يُخمّن |
| العربية والإنجليزية | عناوين وأرقام عربية/إنجليزية في CSV/XLSX؛ حزمة PDF المولّدة الجديدة نصية إنجليزية، ولا تثبت شمول PDF العربي |
| مرجع مكرر أو مفقود أو متعارض | مراجعة مع حفظ البنود؛ تساوي الرصيدين لا يعتمدها |
| 1:N وN:1 | أدلة صريحة وحدود بحث؛ مجموعات الدفع في هذه الحزمة بقيت للمراجعة |
| N:M أو تخصيص غير مثبت | مراجعة، دون بحث مجموعات شامل أو اختيار ترتيب اعتباطي |
| أرصدة كاملة | جسر فقط مع معادلة رصيد وفترة ونطاق وأساس تقرير متوافق |
| أعمار ديون أو نطاق متعدد متعارض | إيقاف المقارنة المتأثرة وطلب مصدر/نطاق مناسب |
| PDF مصور أو صورة عربية | المسار المحلي الموجود ينتج مسودة غير معتمدة؛ ليس مصدرًا لمطابقة مالية مؤكدة |
| AI مساعد | اقتراح محدود يعاد التحقق منه؛ لا يغير رقمًا ولا يعتمد Match ولا يثبت اكتمال التسوية |

رصد اختبار المتصفح الحالي **0/3 أرقام عربية صحيحة حرفيًا** في عينة OCR. هذه فجوة قراءة معروفة، لا نجاح مالي، وبقيت المسودة خارج المحرك والتصدير المعتمد. لم تُضف خدمة خارجية لمعالجتها.

## إعادة التشغيل

من مجلد المشروع بعد تثبيت الاعتمادات:

```sh
pnpm test:reliability:quick
pnpm test:reliability:development
pnpm test:reliability
pnpm test:reliability:performance
pnpm check
```

إعادة حالة بعينها مع كتابة ملفيها ومرجعها محليًا:

```sh
node --experimental-strip-types audit/reliability/run.mjs --case F07 --output work/repro-F07
node --experimental-strip-types audit/reliability/run.mjs --case C03028 --seed 4564764 --output work/repro-C03028
```

تقييم نسخة أخرى يستعمل `--engine-root PATH`. نتائج كل تشغيل في `config.json` و`cases.jsonl` و`summary.json` داخل مجلد العمل. `--no-export` تشخيص مختصر فقط وليس تحققًا للتصدير. `--frozen` إقرار بتجميد التطوير قبل تشغيل الحجز؛ `--freeze-only` يحفظ البصمات و`--freeze-file PATH` يتحقق من ثباتها. الاختبارات المحجوزة المنشورة بعد هذا التقييم تصبح regression معروفة؛ أي دورة تعلم جديدة تحتاج حجزًا جديدًا.

الحكم: **جاهز لاختبار محدود بإشراف محاسب ضمن الحدود أعلاه**. لا توجد مطابقة خاطئة معلومة بقيت دون معالجة في الاختبارات المنفذة. لا تثبت النتائج تغطية كشوف السوق، ولا صحة OCR العربي، ولا كفاية المعلومات المحاسبية في ملف لا يحتويها. الخطوة الميدانية هي حالات موردين مصرح بها من قوالب لم تدخل التوليد، مع قياس نسبة ملاءمة النطاق والوقت اليدوي المتبقي.
