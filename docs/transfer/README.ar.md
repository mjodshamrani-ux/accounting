## تجهيز بيئة جديدة

استخدم الشفرة المتتبعة من GitHub وملف القفل؛ لا تنقل مجلد عمل جهاز سابق أو إعدادات المساعد أو مخازن الاعتماد. بيئة CI المثبتة: **Node 24.19.0، pnpm 11.19.0**. يحتاج بعض مدققات ZIP إلى **Python 3.12 أو أحدث**. إصدارات الاعتمادات في [package.json](../../package.json) و[pnpm-lock.yaml](../../pnpm-lock.yaml)، وأوامر CI في [pages.yml](../../.github/workflows/pages.yml).

```sh
git clone https://github.com/mjodshamrani-ux/accounting.git
cd accounting
git status --short --branch
git log -1 --format='%H %s'
node --version
pnpm --version
python3 --version
pnpm install --frozen-lockfile
pnpm dev
```

التطوير يستمع على loopback؛ استخدم عنوان Vite الظاهر. البناء ثابت بـVite، وليس خادم Next.js. لا يحتاج بدء التطبيق إلى مفتاح API أو حساب أو تنزيل نموذج. تثبيت المكتبات المثبتة بالقفل خطوة إعداد منفصلة عن صلاحية تنزيل نموذج أو إرسال بيانات.

```sh
pnpm lint
pnpm typecheck
pnpm build
pnpm exec playwright install chromium
pnpm test:browser
```

هذا فحص بدء، وليس كل بوابات الإصدار. [دليل التسليم](../reference/DELIVERY.ar.md) يشرح الاختيار أثناء التطوير؛ يبقى سير CI الكامل مطلوبًا قبل الدمج والنشر. لا تحدث القفل أو مكتبة أو snapshot لمعالجة فشل غير مشخص. اختلاف runtime أو غياب المتصفح عائق بيئة، وليس رفضًا محاسبيًا صحيحًا.

## العمل التالي ومعيار إغلاقه

1. **INV-1D** عند المطور النشط: عقد وأوراكل لميراث Plant/Batch والدمج الأفقي المحدود، ثم القارئ ودورة الأصل. لا تتعاون على ملفات مشتركة قبل حسم الملكية؛ راجع PR24 وأحدث خطة. مجاميع صحيحة مع صنف أو مخزن أو batch خاطئ تمنع الاعتماد.
2. **FIN-1** بعده: أساس القبول الجديد خطوة مستقلة في أداة القياس فقط. التنفيذ اللاحق يحتاج عائلة مصدر صريحة، أدوار leaf/control/subtotal/title، إثبات الخريطة والتصنيف والإشارة والمدة والأبعاد، ومنع احتساب الأب والابن مرتين. ثم العامل والقرار والإلغاء والحفظ والاستعادة وExcel ورفع AR/EN، مع حقيقة مستقلة وصفر اعتماد خاطئ ضمن القبول المحدد.
3. **PAY الطويل ثم IC متعدد الدفعات** بحسب تبعيات خططهما؛ لا فتح إعادة كتابة موازية لكل محرك. C-3 للسعة وC-4 لعبء المراجع يحتاجان قياسات فعلية لا عدد fixtures.
4. **AI/OCR وACC** خطط غير مفعلة. اقرأ عقودها وبوابات الخصوصية والأجهزة والاستضافة قبل أي تفعيل؛ وجود runtime ليس دليل منفعة. لا توجد موافقة ضمنية على مزود خارجي أو صلاحيات أو مفاتيح جديدة.

تبقى عينات الشركات المأذونة، الأجهزة الضعيفة، عبء المراجعة، الدقة خارج العائلات المحددة، العربية المصورة وقياس القيمة التجارية أدلة مطلوبة. لا تحول بيانات اصطناعية إلى تحقق ميداني أو تقدير توفير وقت. استخدم بطاقة العمل في دليل التسليم لتثبيت النطاق والميزانية ومعيار التوقف قبل دفعة جديدة.

## ما يجوز نقله وما يبقى خاصًا

ينتقل المصدر العام الموافق عليه وملف القفل والعقود والـfixtures الاصطناعية المراجعة وروابط التشغيل. لا تنتقل ملفات العملاء والجلسات والصادرات الخاصة وصور الشاشة الخام وسجلات الجهاز و`.env` والمفاتيح ومجلدات `work` أو أرشيف الأدلة. `.gitignore` وحده لا يمنع تسرب ملف متتبع أو سر داخل نص مسموح.

راجع كل ملف مقصود ثم ثبت حجمه وبصمته في allowlist؛ لا تعيد توليد الموافقة لكل المجلد. في تحديث توثيقي لا تغير بصمات التوزيع. افحص المرشح المتتبع النظيف:

```sh
node --test scripts/public-content-check.test.mjs
node scripts/public-content-check.mjs --source-export
```

حارس المحتوى يثبت حدودًا محددة ولا يعوض مراجعة المنشأ أو صحة المال. افصل evidence المحلي عن source tree قبل الفحص. لا تحذف الأدلة الخاصة لكي يمر الحارس. تغيير main أو رأس المرشح يتطلب مراجعة الأساس الجديد والتعارضات، لا نشر مرشح قديم بالقوة. لا تعلن التسليم منشورًا حتى تربط SHA النهائي ببوابات CI والنشر وفحص الأصول والمسار الحي المتأثر.
