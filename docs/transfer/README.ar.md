# نقل تطوير تراصف إلى بيئة أخرى

هذه حزمة انتقال محايدة بين المطورين وبيئات التنفيذ. لا تفعّل خدمة سحابية أو نموذجًا أو حسابًا ولا تمنح إذنًا لنقل الملفات المحاسبية. اقرأ [AGENTS](../../AGENTS.md)، ثم [بوابة المرجعية](../README.ar.md). المرجع الحي للعمل التالي هو [الخطة الحالية](../CURRENT-PLAN.ar.md)، وليس نسخة محفوظة من محادثة مساعد.

راجع [حالة تصحيح FIN-1A وحدود الاستئناف](FIN1-STATUS.ar.md) و[سجل المواءمة المحلية](FIN1-RESUME-20261015.ar.md) قبل استكمال PR25 أو ربط المحلل؛ يفصلان تاريخ التصحيح والنموذج السلبي عن تحقق المرشح الجديد.

## الحالة التي بُني عليها هذا التسليم

تستأنف هذه الحزمة محليًا في 15 أكتوبر 2026 على main المحفوظ عند `74e0af54cd592e5b48fc91c661a09a37232264af`، شجرته `18472fb394daf5e01751f22583c2e888e3f1dcd2` ونسخة التطبيق **0.4.54**، بعد دمج G3 للمخزون في [PR32](https://github.com/mjodshamrani-ux/accounting/pull/32). لا يثبت هذا الرقم نجاح CI أو نشر المرشح الذي يضيف FIN أو نشر main74. لم تُعدّل الخطة المشتركة أو الحالة أو بوابة المشروع لاستعارة دليل إصدار آخر.

الدفعة النشطة **INV-1F-G4** في نسخة مطور المخزون، وتوجد فيها تغييرات مرحّلة لم تدخل main المحفوظ. تبقى ملكيتها له، ثم G5 للواجهة وExcel وG6 للتسليم قبل تفعيل FIN. لم تلمس المواءمة تلك النسخة أو تفترض انتهاء العمل بسبب إتاحة ملفات FIN مستقلة. تحقق من أحدث main وحالة الدفعة قبل أي ربط مشترك.

تحتفظ الحزمة بـ[أساس قبول FIN-1](../audits/FIN1-HIERARCHY-FOUNDATION.ar.md) المصحح، وبـ[نموذج source4 السلبي](../audits/FIN1-SOURCE4-PROTOTYPE.ar.md) ذي عقد الاستقبال `fin-source4-bounded-intake-v1`، دون استدعائه من التطبيق أو العامل أو الجلسة. النتيجة التاريخية الصارمة 19/20 للعقد الأول باقية؛ نجاح 8/8 لعقد الاستقبال المنفصل لا يحل محلها. فحوص الرأس المدمج الجديد ومراجعته المستقلة ما زالت معلقة.

في اللقطة التاريخية الأولى كان main عند `296d97f65c55dc3e4ee412119c82ea0ef258dcf7` ونسخة التطبيق 0.4.50، وكان المطور يعد PR24. نجاح [تشغيل main 38641753608](https://github.com/mjodshamrani-ux/accounting/actions/runs/38641753608) و[تشغيل PR25 القديم 38651609155](https://github.com/mjodshamrani-ux/accounting/actions/runs/38651609155) يخص رأسيهما حينذاك فقط؛ لا يثبت حالة هذا الاستئناف.

## تجهيز بيئة جديدة

استخدم الشفرة المتتبعة من GitHub وملف القفل؛ لا تنقل مجلد عمل جهاز سابق أو إعدادات المساعد أو مخازن الاعتماد. بيئة CI المثبتة: **Node 24.19.0، pnpm 11.19.0**. يحتاج بعض مدققات ZIP إلى **Python 3.12 أو أحدث**. إصدارات الاعتمادات في [package.json](../../package.json) و[pnpm-lock.yaml](../../pnpm-lock.yaml)، وأوامر CI في [pages.yml](../../.github/workflows/pages.yml).

```sh
git clone https://github.com/mjodshamrani-ux/accounting.git
cd accounting
git status --short --branch
git log -1 --format='%H %s'
node --version
pnpm --version
python3 --version
pnpm install --frozen-lockfile
pnpm dev
```

التطوير يستمع على loopback؛ استخدم عنوان Vite الظاهر. البناء ثابت بـVite، وليس خادم Next.js. لا يحتاج بدء التطبيق إلى مفتاح API أو حساب أو تنزيل نموذج. تثبيت المكتبات المثبتة بالقفل خطوة إعداد منفصلة عن صلاحية تنزيل نموذج أو إرسال بيانات.

```sh
pnpm lint
pnpm typecheck
pnpm build
pnpm exec playwright install chromium
pnpm test:browser
```

هذا فحص بدء، وليس كل بوابات الإصدار. [دليل التسليم](../reference/DELIVERY.ar.md) يشرح الاختيار أثناء التطوير؛ يبقى سير CI الكامل مطلوبًا قبل الدمج والنشر. لا تحدث القفل أو مكتبة أو snapshot لمعالجة فشل غير مشخص. اختلاف runtime أو غياب المتصفح عائق بيئة، وليس رفضًا محاسبيًا صحيحًا.

## العمل التالي ومعيار إغلاقه

1. **INV-1F-G4 ثم G5 وG6** عند مطور المخزون: العامل والجلسة ودورة الأصل، ثم الواجهة وExcel ثم التسليم. تغييرات G4 المرحّلة خارج هذه النسخة لا تعد مستلمة في هذا المرشح. لا تعدّل ملفًا مشتركًا قبل تحديد المالك وترتيب الدمج.
2. **FIN-1** بعد إغلاق دفعة المخزون وتنسيق الملكية: النموذج الحالي يفحص المصدر الرابع فقط، ولا يثبت تغطية TB أو صحة الخريطة أو الدليل. الربط اللاحق يحتاج المصادر الأربعة وأدوار leaf/control/title، التصنيف والإشارة والمدة والأبعاد، ثم العامل والقرار والإلغاء والحفظ والاستعادة وExcel ورفع AR/EN. تبقى الأدلة المستقلة والبوابات الحالية مطلوبة، ولا يضاف اختيار عائلة قبل اكتمال دورة الأصل.
3. **PAY الطويل ثم IC متعدد الدفعات** بحسب تبعيات خططهما؛ لا فتح إعادة كتابة موازية لكل محرك. C-3 للسعة وC-4 لعبء المراجع يحتاجان قياسات فعلية لا عدد fixtures.
4. **AI/OCR وACC** خطط غير مفعلة. اقرأ عقودها وبوابات الخصوصية والأجهزة والاستضافة قبل أي تفعيل؛ وجود runtime ليس دليل منفعة. لا توجد موافقة ضمنية على مزود خارجي أو صلاحيات أو مفاتيح جديدة.

تبقى عينات الشركات المأذونة، الأجهزة الضعيفة، عبء المراجعة، الدقة خارج العائلات المحددة، العربية المصورة وقياس القيمة التجارية أدلة مطلوبة. لا تحول بيانات اصطناعية إلى تحقق ميداني أو تقدير توفير وقت. استخدم بطاقة العمل في دليل التسليم لتثبيت النطاق والميزانية ومعيار التوقف قبل دفعة جديدة.

## ما يجوز نقله وما يبقى خاصًا

ينتقل المصدر العام الموافق عليه وملف القفل والعقود والـfixtures الاصطناعية المراجعة وروابط التشغيل. لا تنتقل ملفات العملاء والجلسات والصادرات الخاصة وصور الشاشة الخام وسجلات الجهاز و`.env` والمفاتيح ومجلدات `work` أو أرشيف الأدلة. `.gitignore` وحده لا يمنع تسرب ملف متتبع أو سر داخل نص مسموح.

راجع كل ملف مقصود ثم ثبت حجمه وبصمته في allowlist؛ لا تعيد توليد الموافقة لكل المجلد. في تحديث توثيقي لا تغير بصمات التوزيع. افحص المرشح المتتبع النظيف:

```sh
node --test scripts/public-content-check.test.mjs
node scripts/public-content-check.mjs --source-export
```

حارس المحتوى يثبت حدودًا محددة ولا يعوض مراجعة المنشأ أو صحة المال. افصل evidence المحلي عن source tree قبل الفحص. لا تحذف الأدلة الخاصة لكي يمر الحارس. تغيير main أو رأس المرشح يتطلب مراجعة الأساس الجديد والتعارضات، لا نشر مرشح قديم بالقوة. لا تعلن التسليم منشورًا حتى تربط SHA النهائي ببوابات CI والنشر وفحص الأصول والمسار الحي المتأثر.
