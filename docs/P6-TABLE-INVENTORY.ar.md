# P6 — سجل صفوف جدول الصورة في 0.4.22

هذه خطوة لحصر الصفوف وربط أدلتها قبل إدخال الصور في الحسابات. لا يغلق هذا الإصدار P6 ولا يعلن OCR عربيًا موثوقًا أو دعم الصور كمصدر للتسوية. تجربة القراءة السابقة وإخفاقاتها محفوظة كما هي.

## ما يعمل

من الخيارات التجريبية يراجع المستخدم القيم مع قصاصاتها، ثم يحدد جسم جدول مستطيل واحد وحدود صفوفه وأعمدته. كل نطاق داخل الإطار يقع في صف وعمود واحد، بلا فجوات هندسية أو تداخل. يشترط وجود عمود مبلغ، ويمكن فصل المرجع والتاريخ والعملة والرصيد. الحدود تُدخل يدويًا في هذه المرحلة ولا نستنتج أنها صحيحة أو شاملة من ترتيبها وحده.

لكل صف مصير ظاهر: حركة، صف غير مقروء، إجمالي أو غير حركة، أو لم يُصنّف. تربط الحركة بقصاصات يدوية مُراجعة تقع داخل خاناتها وتوافق أنواعها. الرصيد المجاور لا يصلح بدل مبلغ الحركة، والقصاصة لا تُستخدم مرتين. تبقى الكلمات الخام المتقاطعة مع القصاصة، بما فيها ملاحظة القطع، محفوظة؛ سوء تجزئة OCR لا يلغي إدخالًا يدويًا راجعه المستخدم مع الصورة.

الاستبعاد يحتاج سببًا ومراجعة للصف الأصلي. الصف غير المقروء يبقى مشكلة معلنة، ولا يصبح صفرًا أو استبعادًا معتمدًا. تبقى القصاصات المراجعة داخل النطاق دون رابط ظاهرة، وتمنع تسجيل مراجعة النطاق حتى تُربط أو تقع داخل استبعاد مراجع.

مراجعة النطاق تخص كامل الصفحة وحدود الجدول وحصر صفوفه فقط. لا تؤكد كل قيمه بضغط واحد، ولا تجعل الصف غير المقروء سليمًا. يظهر عدد القيم غير المرتبطة والصفوف غير المصنفة وغير المقروءة منفصلًا. تغيّر صف أو سبب استبعاد يلغي موافقاته المتأثرة ومراجعة النطاق؛ تغيّر قيمة الصورة أو قصاصتها يعيد سجل الجدول إلى البداية. تغيير مسودة الإطار أو الأعمدة يلغي الجدول السابق فورًا.

الحفظ ملف JSON ينزله المستخدم صراحةً. الاستعادة تعيد التحقق من صورة PNG الأصلية وبصمتها وبكسلات المعاينة والكلمات الخام ومراجعات القيم، ثم الحدود والروابط وكل استبعاد ومراجعة نطاق. لا تخزين تلقائي أو رفع مستند أو مزود AI جديد. الحفظ والاستعادة لا يمنحان موافقة مالية، والبصمات لا تثبت هوية المراجع أو أصالة مستند الشركة.

## الحدود

جدول واحد من صفحة PNG غير شفافة ضمن عائلة الإصدار السابق: حتى 2 MB و8 ملايين بكسل، ضلع حتى 4096، وحتى 200 صف و8 أعمدة. حد القيم المراجعة المشترك 1000، وملف السجل حتى 16 MB. لا استخراج آلي للجدول، ولا عدة جداول أو عدة صفحات مصورة أو تفعيل JPEG/PDF ممسوح كمدخل مالي.

اسم النوع `visual-table` وحالته `table-evidence-only`. تمنعه بوابات المقارنة والحفظ المحاسبي والاستعادة والتصدير حتى إذا أضيفت إليه أوراق CSV أو إشارات موافقة مصطنعة. فتح هذا المسار للحساب لاحقًا يتطلب نوع مصدر بصري مراجع منفصلًا وإعادة تحقق مشتركة في كل تلك المسارات مع أخطاء الصفوف ومصادر القيم. لا نحول الجدول إلى CSV لتجاوز ذلك.

قد يحدد مستخدم حدودًا خاطئة أو يفوته صف لم يقرأه OCR ولم يراجعه يدويًا. التقسيم الهندسي لا يثبت اكتمال الحركات اقتصاديًا. هذه مخاطرة معلنة، ولهذا لا يوجد اعتماد محاسبي لهذا النوع بعد. لا نوعد بأن التكلفة اقتصرت على مراجعة الاستثناءات؛ الحالة المقاسة تحتاج أربع مراجعات قيم وتصنيف ثلاثة صفوف ومراجعة استبعاد ونطاق.

## الدليل والاختبارات

العينة الاصطناعية محددة قبل القراءة: حركة بمرجع وتاريخ ومبلغ عربي سالب ورصيد عربي مختلف، وصف مبلغ تالف لا يُخمن، وإجمالي ليس حركة. بصمة PNG `20faa7ba31972885baab149ffbf46a1b3c345ebeb3006c7c290b64ac3fa111cb`. ليست عينة ميدانية أو تدريبًا أو Holdout أو قياس تعميم على أشكال موردين أخرى.

نجح محليًا 1066 اختبار وحدة، وفحص TypeScript والبناء والفحص المحدد للملفات الجديدة. يفحص مرجع Python مستقل الصورة والقصاصات والقيم المعلومة والصفوف والبصمات، ويكشف تغيير الإشارة حتى بعد إعادة حساب جميع البصمات العامة. خمس طفرات جديدة تستهدف موافقة قديمة، مبادلة المبلغ بالرصيد، إسقاط قصاصة معلومة، تجاهل بصمة النطاق وتجاوز الحاجز المالي.

حُفظت مراجعة فعلية في متصفح Chromium مع OCR محلي، بالعربية والإنجليزية والجوال، وفُحص السجل مستقلًا. لم تكتمل الدورة المحلية الأخيرة: فشل أولًا مشغل الاختبار في اسم عنصر وتوقيت انتهاء تحميل القارئ، ثم ظهرت مشكلة تمرير إلى زر اللغة عند طول النموذج. أُصلح المشغل وأصبح التمرير ثابتًا أثناء فتح نموذج الصور، لكن صلاحيات البيئة تغيّرت ومنعت بدء Chromium. لذلك لا نسجل نجاح المتصفح المحلي النهائي. بوابة GitHub تعيد الدورة كاملة والفحص المستقل قبل النشر، ونتيجتها توثق منفصلة بعد اكتمالها.

الخطوة التالية: عقد مصدر بصري مراجع يضم السياق الاقتصادي وقيمًا قابلة للتحقق وأخطاء صفوف، مع مسار موحد للمقارنة وحفظ الجلسة وExcel. لا تبدأ هذه الخطوة بإزالة الحاجز الحالي.
