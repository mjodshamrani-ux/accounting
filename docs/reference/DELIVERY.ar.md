# دليل التطوير والتسليم في السحابة

## قبل البدء

اقرأ [AGENTS.md](../../AGENTS.md) والبوابة وخطة المجال. افحص branch وHEAD وremote وحالة الملفات، ثم قارن main البعيد؛ لا تمسح تعديلات المستخدم ولا تفترض أن رابط الموقع يحدد مصدر الشفرة المحلي. لا تعتمد على مسارات جهاز سابق أو مخرجات `work` الخاصة لتشغيل المشروع في السحابة.

بيئة CI الحالية Node 24.19.0 وpnpm 11.19.0. بعض مدققات ZIP تعتمد وظائف متاحة في Python 3.12 وما بعده؛ استخدم بيئة متوافقة مع CI. تثبت الإصدارات في [سير العمل](../../.github/workflows/pages.yml) و[القفل](../../pnpm-lock.yaml)، ولا تحدث الاعتمادات لمجرد البدء.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

## بطاقة العمل

```text
المعرف: مثل INV-1 أو BNK-1
معرف التحدي من CHALLENGES والحماية القائمة أو الشاهد الناقص:
أساس Git:
المشكلة المرئية للمحاسب:
العائلة والنطاق، وما يبقى خارج هذه الدفعة:
الدليل المطلوب وحالات القبول الإيجابية والسلبية:
ملفات التنفيذ والعقود المتأثرة:
ميزانية الوقت/الموارد ومعيار التوقف:
ما نُفذ فعلًا:
الأوامر التي شُغلت ونتائجها والقيود:
الرأس النهائي/التشغيل/حالة النشر:
المتبقي والخطوة التالية:
```

تبدأ الدفعة محدودة: عقد، مصدر مستقل، قارئ، تحقق، جلسة، Excel، واجهة. افصل اكتشاف الغموض المحاسبي عن إصلاح CSS أو wiring. تقسيم العمل إلى تنفيذ ومراجعة متخصصة مفيد، لكنه لا يضمن الصحة بسبب اسم النموذج؛ الشاهد المستقل هو الفيصل. لا يحتاج أي مطور إلى تشغيل وكلاء متعددين كي يتبع هذه المرجعية.

في عمل المحرك استخدم [سجل التحديات](CHALLENGES.ar.md) لربط المهمة بمشكلة المحاسب والدليل المطلوب والقبول. صنّفها عيبًا مثبتًا أو فجوة دليل أو توسعة نطاق؛ لا تعامل كل خطر موثق كأنه عيب قائم، ولا كل اختبار مقترح كأنه نُفذ.

## الاختبارات

خلال التطوير شغل ما يتأثر فعلًا. في تغيير محرك: وحداته وعقده وأوراكل الصادرات والطفرات والمتصفح ودورة الأصل. في تغيير مشترك: اختبر المجالات المتأثرة، خصوصًا ترتيب المصادر والتنقل والعامل. قبل إصدار التطبيق تنفذ بوابات المستودع الكاملة دون تخفيف.

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm test:mutation-runner
pnpm test:source-families:ci
pnpm build
pnpm exec playwright install chromium
pnpm test:browser
pnpm test:browser:main-integration
pnpm test:browser:domain-navigation
pnpm test:browser:reconciliation-entry
pnpm test:browser:unified-workspace
```

هذه نقطة دخول وليست بديلًا عن جميع أوامر [CI](../../.github/workflows/pages.yml)، الذي يشغل أيضًا الطفرات المجزأة والأوراكل وPDF الطويل والصادرات المستقلة والبوابات المتخصصة. لا يعاد اختبار مالي شامل محليًا بلا داع لكل تعديل لغوي، لكن لا تحذف بوابة بعيدة أو تستخدم skip لتزعم نجاح إصدار.

## النشر العام

[public-safe-manifest.json](../../public-safe-manifest.json) قائمة دقيقة بالأسماء والأحجام والبصمات. راجع الملفات المقصودة ثم أضف أو حدث سجلاتها فقط. لا تولد الموافقة آليًا من كل محتويات المجلد، ولا ترفع بيانات المستخدم أو لقطات الشاشة الخام أو سجلات الجهاز. يجب أن تبقى `work` والمخرجات الخاصة خارج المصدر المنشور.

يفحص [public-content-check](../../scripts/public-content-check.mjs) المصدر النظيف والتصدير والحزمة. التشغيل داخل مجلد يحتوي مخرجات خاصة قد يرفض بحق؛ الحل فحص تصدير Git نظيف للمرشح المحدد، لا حذف الأدلة أو تعطيل الحارس. تحديث وثائق فقط لا يحتاج تغيير بصمات توزيع التطبيق أو رقم إصداره.

```sh
node --test scripts/public-content-check.test.mjs
node scripts/public-content-check.mjs --source
node scripts/public-content-check.mjs --source-export
node scripts/public-content-check.mjs --dist
```

اختر الوضع والجذر المناسبين؛ `--dist` يتطلب بناءً موجودًا و`--source-export` يستخدم قائمة Git المتتبعة. كل ملف جديد، بما فيه هذه الوثائق وAGENTS/CLAUDE، يحتاج إدراجًا صريحًا آمنًا. لا تغير ملفات التراخيص أو الأوراكل المجمدة لتجاوز المنسق.

## إغلاق المهمة

راجع الفروق والعقد والنتائج، وارفع وفق تفويض صاحب المشروع الساري. قبل تحديث main تحقق من أنه لم يتحرك؛ لا force push ولا استبدال لتعديلات السحابة المتزامنة. لا تعلن اكتمال النشر حتى تنجح وظائف CI والنشر للرأس المطلوب، ثم تحقق من بايتات الموقع والخط والواجهة ومسار العمل المتأثر.

في مهمة توثيق فقط فرّق بين رفع المراجع إلى GitHub وبين إصدار تطبيق جديد؛ اعرض حالة CI الفعلية دون استعارة نتيجة الأساس القديم. تبقى أوامر النشر والفحوص الحالية كما هي.

تحدث [الحالة](STATE.ar.md) فقط عندما يتغير الدليل، و[الخطة الحالية](../CURRENT-PLAN.ar.md) عندما يتغير العمل التالي، وخطة المجال عند إنجاز دفعة أو اكتشاف فجوة. اذكر ما لم يمكن اختباره بدل ملء الفراغ بتخمين.
