هذه حالة وجود وتنفيذ محدود، وليست ترتيب دقة أو نسبة نجاح مقارنة بين المجالات. تختلف صيغ الاستيراد والعائلات المعتمدة بين الأدوار؛ لا يعني وجود قارئ PDF مشترك أن كل دور يقبل كل PDF. يرجع إلى واجهة الدور وملف `*-io.ts` وعقد العائلة.

يوجد [مولّد موثوقية قائم](../../audit/reliability/manifest.mjs) بإصدار `tarasuf-independent-2.1.0` وتوزيع معرف لـ5000 حالة اصطناعية. وجود الجرد لا يعني أن جميعها نجحت أو شُغلت على هذا الرأس؛ لا ننسب إليها نتيجة من عدد اختبارات الوحدات. يعاد استخدام المولّد والمدقق الحاليين وتوثق نتائج التنفيذ الفعلية بدل إنشاء آلاف النسخ المتشابهة.

الواجهة موحدة بخط ثمانية الأصلي، ورفع A4 التفاعلي، واختيار نوع واحد، واحتفاظ العمل وأقسام الصفحة المشتركة، بالعربية والإنجليزية. التفاصيل في [عقد الهوية](../WORKSPACE-IDENTITY.ar.md).

## ما بقي مفتوحًا

الحسابات وتسجيل الدخول والخروج ولوحة المالك وإحصاءات الاستخدام والمؤسسات والتجارب المجانية والفوترة **ليست قدرات منفذة في هذا الأساس**. لها [خطة توسع ACC](../roadmap/accounts-privacy-business.ar.md) منفصلة؛ لا تفعّل هذه الإضافة التوثيقية أي قياس أو اتصال جديد.

توجد حالة دليل الهوية [P1V206 وعقد شاهدها](../../audit/p1v206-source-proof-v1/frozen/contract.json) في الخطة السابقة ضمن العمل المفتوح؛ لا يغلقها نجاح العرض أو تعديل توثيقي. يعاد تحديد شاهدها وحدودها قبل إعطاء قرار جديد.

## تحديث هذه اللقطة

عند إصدار فعلي جديد: سجل الرأس والشجرة والتشغيل المنشور، وحدّث خلايا القدرات التي تغيرت فقط، واربط النتيجة باختبار أو عقد. عند تغيير الخطة فقط: حدّث [قائمة التنفيذ](../CURRENT-PLAN.ar.md) دون إعادة تسمية العمل المخطط «منجزًا» أو استبدال أساس التحقق التاريخي.
