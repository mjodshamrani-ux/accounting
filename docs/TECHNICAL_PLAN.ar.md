## 1. عقد المنتج

- موقع ثابت متوافق مع GitHub Pages، بلا واجهة خلفية لمعالجة الملفات وبلا حساب إلزامي.
- XLSX/CSV وPDF نصي بلا صور؛ مورد واحد، جهة واحدة، حساب ونطاق اقتصادي واحد، وعملة واحدة. PDF يتطلب حدود أعمدة صريحة ومراجعة جميع الصفحات والصفوف مع الأصل؛ لا OCR ولا افتراض دعم كل قالب.
- مساران: حركات مقابل حركات، وبنود مفتوحة مقابل بنود مفتوحة. الأزواج المختلطة مرفوضة في النسخة التجريبية.
- المطابقة الآلية: مرجع محافظ غير فارغ + مبلغ مطابق + تاريخ ضمن نافذة معلنة + مرشح وحيد في الطرفين. الغموض لا يُحسم بترتيب الصفوف.
- لا تخصيص دفعات، ولا N:M، ولا OCR، ولا تكامل، ولا ترحيل قيود، ولا إرسال بيانات مالية.
- مقارنة الحركات مستقلة عن التحقق من الأرصدة. لا زر أو رسالة تدّعي اعتمادًا محاسبيًا آليًا.

## 2. تدفق الواجهة

اختيار الملفات أو مثال اصطناعي ← تأكيد الأوراق والعناوين والأعمدة ونوع التقرير والإشارات والتواريخ والنطاق ← تحقق ومقارنة ← استثناءات ومراجعة مع مصادر ← تصدير ورقة عمل.
تغيير البيانات أو إعدادات المطابقة يبطل النتائج والقرارات السابقة. لا يجوز تشغيل المهمة الجديدة على نتيجة قديمة.

## 3. طبقات مستقلة

1. File IO: قراءة XLSX/CSV وPDF النصي داخل Worker؛ حد 8 MB لكل ملف، ونحو 20,000 صف، و100 عمود، و12 ورقة ومليون خلية للمصنف. PDF له حدود إضافية: 20 صفحة و20 عمودًا و100,000 عنصر نصي ومليونا محرف و4096 محرفًا في الخلية. تُرفض الصور والملفات والبنى غير المدعومة بدل اقتطاعها؛ حدود الأعمدة يحددها المستخدم، ومراجعة الاستخراج شرط قبل المقارنة. يُحفظ رقم صفحة المصدر ويُعاد استخراج الأصل قبل التصدير. اختيار الورقة وصف العناوين ومعاني الأعمدة صريح؛ لا تشغيل صيغ/ماكرو أو روابط خارجية. راجع [حدود PDF التفصيلية](PDF.ar.md).
2. Normalization: أرقام عربية/هندية، فواصل متفق عليها، مبالغ بوحدات عشرية صحيحة، تواريخ بصيغة مؤكدة، مراجع تحافظ على الأصفار البادئة.
3. Source accounting: كل صف له مصدر وحالة: حركة أو مستبعد صراحة أو خطأ. لا إسقاط صامت ولا افتراض أن كشف البنود المفتوحة يحتوي كل حركات الفترة.
4. Validation: نطاق اقتصادي مؤكد، تاريخ قطع، اتجاه مديونية، تواريخ ونطاق مصدر، أرصدة افتتاح/ختام عند توافرها. تحقق اتساق لا شهادة اكتمال.
5. Matching: قواعد حتمية، منع إعادة استخدام الحركة، كشف تكرار/غموض، اقتراحات دون اعتماد.
6. Review: إظهار الطرفين وأسباب الربط، موافقة بشرية محلية وفك الربط، ملاحظات. الاعتماد البشري لا يثبت تلقائيًا سبب فرق.
7. Bridge: من المورد إلى الدفتر؛ آثار البنود رقمية منفصلة عن أسبابها، فرق افتتاحي غير مفسر ظاهر، لا موازنة اصطناعية. الاتزان لا يساوي صحة التسوية.
8. Export: Excel بملخص، مصادر، مطابقات، استثناءات، مستبعدات، إعدادات وإصدار وقرارات؛ نصوص المصدر كخلايا نصية لا صيغ قابلة للتنفيذ.

## 4. الخصوصية

- التطبيق وملحقاته تُخدم كملفات ثابتة. المحتوى المالي وأسماء الملفات تبقى بالمتصفح.
- لا تحليلات ولا تسجيل جلسات ولا تقارير أخطاء شبكية ولا خطوط خارجية في مساحة العمل.
- سياسة CSP لتقييد الاتصالات والسكريبتات؛ GitHub Pages يدعم meta CSP لكن لا يمنح تحكمًا عامًا في رؤوس HTTP. لا ندّعي دعم ضوابط headers غير المتاحة.
- لا حفظ للمعاملات في localStorage/IndexedDB؛ قوالب تعيين الأعمدة اختيارية محلية دون قيم أو أسماء الموردين. فقدان الجلسة غير المصدرة موضح.
- معالجة الملف في Worker يمكن إنهاؤه؛ حماية من استجابة قديمة واستبدال حالة تشغيل أحدث.
- العمل بعد تحميل التطبيق دون إنترنت يُختبر. إعادة فتح الموقع بلا إنترنت وPWA مؤجلان ما لم يُنفذا ويُختبرا فعليًا.
- مراجعة المكتبات وتثبيت lockfile. فحص مخرجات البناء للموارد الخارجية واتصالات التطبيق؛ لا إرسال بيانات في URL أو logs.
- الحماية تخص سلوك التطبيق، وليست ضمانًا لجهاز أو إضافات متصفح مخترقة.

## 5. الاختبارات وبوابات الإصدار

- اختبارات مبالغ وإشارات وتواريخ غامضة وأصفار مرجعية وتكرار ومجاميع فرعية.
- حفظ إجمالي الصفوف والمبالغ ومنع استخدام الصف مرتين، ومطابقة لا تعتمد على ترتيب المدخلات.
- فرق صفر مع بنود متعاكسة يبقى غير مفسر، وفروق الرصيد الافتتاحي لا تُخفى.
- تغيير إعداد يلغي نتائج قديمة، وإلغاء Worker ينهي المعالجة.
- اختبار XLSX/CSV حقيقي وفتح مخرجات Excel برمجيًا للتحقق من الإجماليات وأن نصوص المصدر ليست صيغًا.
- اختبارات تشخيص البناء وtypes، اختبارات واجهة وظيفية عند طلبها، واختبار نشر بمسار GitHub project Pages فرعي.
- الفشل في إصدار يبقى مسجلًا. إصلاح مبني على holdout يجعل الحالة regression لذلك الإصدار ولا يمحو فشل الإصدار السابق.
- لا نشر بوصفه منتجًا مثبتًا؛ نسخة تجريبية مع حدود مدخلات ودقة معلنة.

## 6. نشر GitHub

- المستودع الذي حدده المستخدم: [mjodshamrani-ux/accounting](https://github.com/mjodshamrani-ux/accounting). كان عامًا عند الرفع؛ لم نغيّر خصوصيته. مصدر Pages مضبوط على GitHub Actions.
- إعداد GitHub Actions: تثبيت من lockfile ← اختبارات ← typecheck ← بناء static ← رفع artifact ← نشر Pages.
- دعم root أو /repository/ دون روابط أصول مكسورة؛ لا أسرار ولا ملفات مالية في المستودع.
- نشر المنتج يحتاج نجاح workflow والتحقق من عنوانه الفعلي. تجهيز workflow وحده لا يعني النشر.

## 7. التسلسل والميزانية السابقة

الاكتشاف 24 ساعة → تجميد المواصفات 16 ساعة → بناء تجريبي 120 ساعة → تقييم 32 ساعة. هذه حدود تخطيط وليست ساعات عمل مسجلة أو تكاليف مأذونًا بها.
بناء نسخة اصطناعية الآن مأذون به من المستخدم، لكنه لا يسد فجوة الاكتشاف. توثيق العينة الميدانية والدقة المستقلة والدفع والعودة يبقى معلقًا حتى تتوافر بيانات فعلية.

## 8. معنى الاكتمال الحالي

المكتمل ضمن المسارات المختبرة: استيراد محلي، مراجعة قابلة للاستخدام، مطابقة محافظة، تصدير للمصادر والقرارات اجتاز فحوص Excel، واختبارات برمجية ومتصفحية ناجحة ونشر GitHub Pages تحقق عنوانه فعليًا.
غير مثبت بمجرد اكتمال البرمجة: دقة شاملة 100%، زمن وفر ميداني، قابلية تجارية، ملاءمة جميع قوالب ERP، وموافقة أمنية لدى أي جهة.

## قرار تنفيذ 0.2: أولوية منع المطابقة الخاطئة

المرجع الموحد يستخدم للاقتراحات فقط. المطابقة الآلية تشترط تطابق المرجع الأصلي بعد إزالة الفراغ الطرفي فقط، وعدم تكرار مرجعه الموحد في أي طرف، مع المبلغ الموقّع ونافذة التاريخ. التكرار ولو اختلفت مبالغه يمنع الاعتماد الآلي.

الشات قارئ للأدلة ولا يملك واجهة كتابة للمحرك. نموذج المتصفح الجاهز اختياري لفهم السؤال واقتراح معرفات، دون تنزيل يبدأه التطبيق أو خدمة خارجية. لا تعاد صياغة الأرقام بواسطة النموذج؛ قوالب الشرح تقرأ القيم من المحرك. كل فرضية حسابية متساوية تبقى للمراجعة ما لم تستوفِ قاعدة مطابقة مستقلة. لم تنفذ مطابقة N:M أو تعيين أعمدة بواسطة AI في هذا الإصدار؛ لا تُعتمد دلالات الوصف أو أصالة المستند حسابيًا.

الحالة الحالية للمساعد: العربية تعتمد القواعد. مسار نموذج الجهاز مخصص للأسئلة الإنجليزية عند توفره مسبقًا، ولم يُختبر نموذج محلي فعلي؛ اختبارات واجهة النموذج تستخدم بديلًا اصطناعيًا ولا تثبت جودة الاستدلال التوليدي.
