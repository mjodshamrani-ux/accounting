## Review-only sections beside the families

Each section sits inside its domain's workspace beside the existing family, whose decisions, session and workbook stay as they are. It sends its files to the worker (its own, or the workspace's in clearing and allocation), accepts a result only for the bytes it sent and after recomputing it on the page, and offers no decision, session or Excel. Its states (held, missing, difference, consistent and the contract's codes) are review evidence, never approval. Keep the native file inputs, the accountant's scope confirmation where the section asks for one, and the collapsed `details` where it has one.

These sections are not wired to one shared component yet; inspect each before a shared change, and test each section's own browser acceptance with the domain's.

Plans contain implemented history **and future work**. Verify current source families, formats, gates and scope in code/state before exposing a capability. For example, generic PDF parsing does not authorize every domain to accept arbitrary PDF. A source counter must reflect the chosen path, not a universal “two files” promise.

For a shared change, verify all twelve domains retain one selector, appropriate main landmark/heading, correct required roles, original upload controls, preserved state across navigation/language, and processing locks. For a local change, test its domain plus affected shared behavior. Do not run only supplier tests and infer parity.
