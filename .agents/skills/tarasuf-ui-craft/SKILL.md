# Tarasuf UI Craft

Improve the accountant's ability to understand, verify and act while preserving Tarasuf's recognizable design. Optimize in this order: financial truth, traceable evidence, privacy, usable workflow, visual craft. Treat distinctiveness as a goal; gradients, purple, depth and original SVG artwork are not evidence of poor design.

## Choose one mode

| Mode | Allowed work | Required output |
| --- | --- | --- |
| **Audit** | Inspect source and available rendered states; no edits | Evidence-linked findings, preserved strengths, priorities, proposed direction |
| **Refine** | Implement the explicitly requested bounded improvement | Coherent diff, before/after evidence, regression checks |
| **Design** | Design and implement an authorized new component or experience within the identity | Purpose, states, domain mapping, composition rationale and acceptance evidence |
| **Review** | Inspect candidate diff and run scoped checks; no edits unless requested | Regressions, acceptance results, remaining unknowns |

Default to Audit for assessment or unclear change scope. Use Refine for an explicit polish/fix request. In Design, propose only if implementation was not requested. Infer routine choices; do not add confirmation to authorized work. A major identity replacement or change in financial meaning needs separate authorization and lies outside visual refinement.

## Execute a bounded design loop

1. **Understand the decision.** Identify the accountant, workspace, stage (sources → reconcile → review → explain → export), immediate decision and success criterion. Classify the surface as operational, explanatory or mixed. Record scope and excluded contracts.
2. **Inspect the system.** Read relevant identity documents, rendering components, translations, source-role bindings and tests. Find existing components/tokens before inventing replacements. Capture baseline states with synthetic data when possible.
3. **Diagnose with evidence.** Record `location → observed behavior → consequence → severity → evidence`. Separate reproduced defect, source-code risk, hypothesis and future idea. Describe the actual problem (e.g. clipped negative sign), not merely “AI slop.”
4. **Prioritize.** P0: misleading financial authority, lost evidence/work or privacy leak. P1: blocked interaction, hidden material warning, unreadable amount or accessibility barrier. P2: hierarchy, consistency or comprehension friction. P3: optional expression. An aesthetic score cannot offset P0/P1 failure.
5. **Preserve deliberately.** List working assets, controls, state behavior and visual qualities that must survive. Prefer no change to unsupported cosmetic churn.
6. **Set direction.** Write a brief: user decision; precise product character; accounting metaphor; focal information; one purposeful signature; reuse; constraints; acceptance checks. For substantial new work, compare two compositions against comprehension, identity, risk and cost, then choose with reasons. Distinguish operational density from expressive scenes.
7. **Implement the selected scope.** Preserve source ordering, state ownership, real inputs and contracts. Do not touch engines, policies, data flows, session/export formats or service activation to simplify a screen. Report a required contract change as a separate task. Choose pass order from dependencies, not a fixed ritual.
8. **Compare.** Use identical viewport, language, data and state before/after. Inspect text, signs, evidence navigation, interaction and full motion cycle as applicable. A screenshot does not prove a control works.
9. **Verify.** Execute scoped gates from verification and current delivery rules. Test positive, incomplete and failure states. Use evidence from this candidate, never a past green run. When editing the skill, run `python3 .agents/skills/tarasuf-ui-craft/scripts/validate.py --self-test`.
10. **Report.** State mode/scope; changes and preserved identity; evidence/severity; checks actually run/results; risks/unverified states; branch/commit and delivery status. Do not claim WCAG conformity, accounting accuracy, device performance or deployment without evidence.

## Decision boundaries

- Treat document/code disagreement as a finding. Cite both, inspect active styles/tests/history, preserve the stronger financial/accessibility constraint and escalate only the unresolved identity/contract decision. Do not rewrite governing documents to legitimize a preference.
- Never turn a proposal, incomplete read, equal total or restored session into an approved result through color, label, motion or enabled action.
- Keep financial files and review evidence local. No external fonts, analytics, image services, telemetry or model downloads for design work. Public examples must be synthetic and identified.
- Preserve original Thmanyah headings, brand geometry, blue–purple identity, upload artwork and native inputs. Surrounding composition can improve within scope.
- Keep one type selector and retained work across all current domains. Supplier reconciliation has no privileged product status.
