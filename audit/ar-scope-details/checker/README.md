# Independent AR workbook/session evidence checker

This checker was authored without reading or importing product implementation, product tests, product fixture generators, or product proof/browser drivers. Allowed inputs are the sealed preparation contract, literal manual truths and original sources, the separately authored preparation oracle, the previous independent legacy export audit, the documented export/session protocol, and actual exported/session/result evidence. Product result JSON is a claim checked against independently verified originals; it is never an expected result.

Package this directory at `audit/ar-scope-details/checker/`, beside immutable `oracle/ar_oracle.py`, `CONTRACT.ar.md`, and `fixtures/TRUTHS.json` with original fixture directories. Python standard library only. The optional `--prep` override selects the sealed preparation directory for an external evidence check.

```sh
python3 -B audit/ar-scope-details/checker/check_exports.py --index evidence/proof/evidence-index.json --output-dir evidence/independent-proof
python3 -B audit/ar-scope-details/checker/check_exports.py --index evidence/browser/evidence-index.json --output-dir evidence/independent-browser
python3 -B audit/ar-scope-details/checker/check_export.py actual-export.xlsx --bundle audit/ar-scope-details/fixtures/one-invoice-open-differs/bundle.json --session actual-session.json --output report.json
python3 -B audit/ar-scope-details/checker/self_check.py --output-dir evidence/independent-self-check
```

Exit 0 means verified; exit 1 means a semantic/evidence rejection or malformed evidence. Index checks preserve per-artifact receipts and a `REPORT.json`. Give each run a distinct output directory to preserve failed attempts. The checker verifies every declared artifact digest and byte count, chooses sealed originals for the 75 preparation cases, and reconstructs additional synthetic lifecycle inputs from actual source snapshots plus executed scope/family options. Browser `expectedMatched` values are ignored. Literal manual truths are checked only when sealed case identity and source hashes apply.

All nine tables are checked from raw OOXML, using workbook relationships, literal string escapes, actual cell references, and source base64 chunks. Checks include exact source bytes/hash, header and table order, complete raw inventory, physical membership, original kind/own document/date/money and related negative evidence, source scope cells and block boundaries, five inherited cells plus parent coordinates, descriptive open text, exact totals and their availability, reading selections, separate rejected inventory refs, coverage disclaimer, no allocations/completeness, and legal ordered decision replay bound to exact bytes/readings/scope. Saved sessions have exactly the documented envelope and original file fields, with no derived cache. Result and restored-result claims are compared with those independently verified tables. Legacy coverage is finite: canonical AR and declared role aliases from the preparation oracle, plus the actual legacy-session lifecycle export. Generic old own-document role confirmation and arbitrary old reading configurations are not claimed.

Protocol distinctions from preparation diagnostics are explicit. Structurally invalid sources may omit an authoritative scope object while keeping every raw header/detail cell and source rejection. Total-overflow sources keep their valid scope object and cite every contributing movement inventory row. Root diagnostics may stop before downstream parser cascades; exported categories must be independently supported, preserve the sealed manual required categories, and retain each exported direct cause's physical row. `data-after-end` and `repeated-or-late-header` are equivalent only for literal repeated markers after the recorded end. Diagnostics cannot reference foreign or missing inventory IDs. Unparsed rejected details can retain header/detail classification without becoming financial members. The external wrong-original-amount selection and identical-original-hash guards may suppress all eligible construction before parsing; both require exact original inventories and explicit independently proven rejection. These two conservative suppressions are applied after, and never change, the sealed manual/oracle comparison. Legacy appended raw/provenance fields remain unavailable as documented.

`self_check.py` preserves six unittest methods with four positive original-source cases and nineteen semantic corruption controls. They include original/open substitution, source chunk tampering, inventory/header/parent loss, foreign membership/amount/document/date, double coverage, invented allocation/completeness, cached session state, family/reading changes, and four incorrect replay forms. The unchanged claims are accepted first; corruptions must raise `CheckFailure`, so ZIP CRC failures and generic runtime exceptions cannot count as detection. A separately constructed raw OOXML original checks literal numeric `100.00`, a zero-height row, and text format `;;;`. Its round-trip controls are synthetic checker tests, not actual product export acceptance.

The final actual proof receipt verifies 75 sealed corpus exports plus nine synthetic lifecycle exports/sessions/results/replays. The final browser receipt separately verifies 114 actual downloaded workbook/session pairs across the two languages and three widths, including eighteen reopened/accepted/restored lifecycle pairs. Browser `expectedMatched` claims are ignored. Early failed reports are retained, including the concrete merged-cell lexical-original defect that required a reader fix. Five product rejection summaries in the proof index lack the rejected bytes and execution records needed for independent replay; they are retained as claims and are explicitly not counted as independently verified rejection outcomes.

Coverage is finite. This does not prove every Excel/OOXML extension, encryption, macros, external links, every style or package repair, browser rendering, worker races, performance, field accuracy, privacy history, accounting completeness, receipt allocation, deployment, CI, or publication. The browser receipt checks the downloaded evidence and does not independently assert visual rendering quality. Every fixture and control is synthetic; field originals: zero.
