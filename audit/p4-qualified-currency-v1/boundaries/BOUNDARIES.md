# Boundary clarification for the independent qualified-currency contracts

This separate clarification preserves the original draft and dot-format addendum byte-for-byte. It changes only which boundary the named tamper actions test and makes the existing private snapshot semantics explicit. Original draft manifest: 83c0ce2ccafa08bfff3f20bfa0831eae145434c98ba779cada4c421d38afda79. Dot-format addendum manifest: 1056e5b2a6bf558766475ef53f1c44eee0865528517474b2444df33b044a7852. All original economic truth, PDFs, CSVs, signed minor units, mandatory positive/refusal outcomes and existing family behavior remain unchanged.

## Product input and publication

The product API remains `new SectionDerivedReadingSession(source, reading, extractionRevision, decimals)` and its existing `replaceSource`, `updateReviewer`, `inspect`, `selectProposalIds`, `recordReviewerDecision` and `apply` methods. It accepts no external sidecar or deserialized currency artifact as review/financial authority. No new sidecar import or choice-specific public method is required.

`apply` publishes only a result constructed from its owned original snapshot, current owned review/receipt and fresh native CSV replay. Before publication it validates its generated currency context, reviewed original numeric choice and rebound derived choice against those owned facts. Tests of corrupted generated choice fields are private-copy deliberate faults in this construction/replay path. They do not assume a public API that consumes arbitrary supplied derived choices or sidecars. Failure suppresses the entire artifact and preserves original bytes.

Input choice/currency descriptors are guarded before copying. Once an operation or review decision has taken its private entry snapshot, later mutation of that operation's caller SourceFile, Mapping, acknowledgement/decision object or arrays does not mutate the private snapshot. Such late mutation alone does not advance session generation and is deliberately ignored. Successful output still agrees exactly with the original entry snapshot, current owned review and frozen expected CSV. That is an ownership positive, not a stale-source failure. Apply's existing currentSource/currentReading/revision/exponent arguments retain their current comparison contract: changing an object before offering it as a new current input may fail that comparison. The successful controls mutate the caller objects after Apply has taken its own input snapshots, rather than supplying already changed current inputs.

The phrase 'change source/reading/choice/header during await' means invoking `replaceSource` with a replacement source/reading/revision/exponent on the live session, or invoking `updateReviewer`/another review operation that invalidates its receipt and advances generation. Changes to an owned original choice can be represented by a replacement reading through existing `replaceSource`. The pending operation must refuse and publish no artifact after that generation change. A changed original byte/header intended to test original replay is present in the supplied input before its snapshot or is submitted through `replaceSource`; it is not a volatile mutation of the old caller buffer after entry.

## Receipt timing

Preserve the existing structural inspect/review versus full Apply validation boundary. A late unreadable amount, unresolved movement reference or other existing final reading refusal may still produce a structural selection/review. Apply must refuse the whole artifact and consume/invalidate its current owned receipt before awaited replay, as the existing API does. A blocked case's `newCurrencyReceipt: false` means no surviving usable currency receipt after refusal, not a universal promise that no structural interpretation receipt was ever minted. No new full financial preparation or copied dry-run is required before minting.

The new narrow monetary-context admission guards are different: an unadmitted or conflicting code, selected exponent inconsistent with the admitted fixed policy, or missing/invalid acknowledged original numeric choice where ambiguous must refuse before minting a currency derivation receipt. Inspect may still show source evidence where the existing structural flow permits it. This early obligation is restricted to the new currency/precision/choice trust contract and must not broaden existing families or move every late semantic refusal earlier.

## External downloaded-file verification

Downloaded CSV, original PDF and provenance are audit artifacts. An edited sidecar is not submitted to the session API and has no authority to alter the session. The original draft's `sidecar-currency-tamper` and `sidecar-precision-tamper` actions test a strict independent artifact checker, proposed maintained CLI `python3 scripts/section-qualified-currency-check.py <proof-directory>`. Its input is a native browser proof directory containing the declared observations and actual downloaded files. Its expected values come only from frozen independent source/truth manifests. It checks exact required case/language identities, nonempty mandatory coverage, original/CSV hashes and rows, every source link and currency cell, exponent/policy, original and rebound choice bindings and explicit no-financial-approval metadata. Missing, extra, duplicate or changed sidecar context refuses checker acceptance; an empty or partial report earns no success.

These actions earn the limited statement 'the independent checker refuses modified downloaded provenance'. They cannot earn a claim that the product rejected a sidecar import, because there is no such import. Tamper tests use new disposable copies of the native downloads and never edit frozen inputs or earlier successful proof bundles. `provenance-without-original-review` has two distinct proofs: attempting product `apply` without the current owned original review/receipt refuses; a copied download whose sidecar claims such review inconsistently also fails independent artifact checking. A foreign sidecar itself is never an input to the product proof.

## Exact action interpretation and precedence

`boundary-actions.json` names the original action IDs affected by this clarification and their exact boundary. For those IDs this boundary interpretation takes precedence over ambiguous original 'supply/tamper during await' wording, without changing expected money. `ownership-controls.json` adds three mandatory successful ownership controls and two concrete session-generation refusal controls. It does not replace any existing refusal or original failure evidence. Independent precode review and later implementation/native/browser acceptance remain separate.
