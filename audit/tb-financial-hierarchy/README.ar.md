# FIN-1A أساس قبول العرض الهرمي

**جميع المصادر اصطناعية. هذه حزمة قبول قبل التنفيذ، وليست دعمًا في التطبيق أو اختبارًا لنجاح المحرك.** لم تتغير ملفات المنتج أو النسخ أو الجلسات. العمل مستقل عن دفعة المخزون النشطة؛ تفعيل FIN يحتاج فتح دفعة محرك واحدة لاحقًا وفق الخطة.

يشغّل الأمر التالي من جذر المستودع فحص البصمات ثم اختبارات الأوراكل، دون شبكة أو اعتماد خارجي أو كتابة فوق الأصول المجمدة:

```sh
python3 -B audit/tb-financial-hierarchy/run.py
```

أمر CI المكافئ لا يحتاج تثبيت حزمة:

```sh
python3 -B -m unittest discover -s audit/tb-financial-hierarchy -p 'test_*.py' -v
```

نجح تشغيل المنفذ المحلي على Python 3.9.6. تحقق مالك التسليم من النسخة النهائية على Python 3.12.14 ونجحت المجموعات الـ13، بما فيها عضوية الملفات المتداخلة وغير CSV. الشفرة تستعمل المكتبة القياسية فقط.

## النطاق والعد الصحيح

القصة الواحدة بعملة SAR تشمل حساب `0010` في بعدين مختلفين، وحساب `001` لا يختزل إلى `0010`، ومخصصًا مقابلًا للأصل بعلامة سالبة، وصفرًا صريحًا، وأصلًا ذا مستويين من مجموعات التحكم. المدخلات أربعة أدوار: TB، خريطة، دليل عرض، وقائمة هرمية ذات `Node ID` و`Parent ID` و`Kind`. لا تعتمد العلاقة على ترتيب السطور أو اسم الحساب أو ألوانه.

الحزمة **18 حالة، منها إيجابيتان و16 سلبية، و72 ملف CSV**. هذه **قصة مالية واحدة وعائلة مصدر هرمية واحدة وتمثيلان CSV ومنتج واحد وحاوية واحدة**؛ إعادة ترتيب الصفوف والأعمدة ليست عائلة جديدة. لا يوجد holdout أعمى أو مصدر شركة أو دليل ميداني. المولد والأوراكل كتبتهما جهة التنفيذ نفسها؛ استقلالهما هنا عن كود المنتج وحساباته، وليس استقلالًا بشريًا أو ماليًا مضمونًا.

الإيجابية الأولى ترتيب أصلي، والثانية نفس الحقائق بترتيب الصفوف والأعمدة معكوسًا. تقارن اختبارات الحقيقة والأعضاء والأصل والإحداثيات. لا يجمع الأوراكل مبالغ الأب والطفل معًا: الأصول 120000 بوحدات SAR الصغرى، والالتزامات 50000، وحقوق الملكية 70000؛ مجموع TB المدين والدائن 130000 لكل جانب. قيم الآباء ضوابط فقط، بينما الأوراق المالية الطرفية هي مساهمات العرض. عنوان التقرير لا يملك مبلغًا ماليًا.

## العقد والأوراكل

[contract.json](contract.json) يثبت النطاق والحدود والسياسة والحقيقة اليدوية قبل تقييم أي منتج. [generate.py](generate.py) يكتب UTF-8 CSV ولا يستورد الأوراكل أو المنتج. [oracle.py](oracle.py) يعيد قراءة البايتات باستخدام `csv` و`Decimal`، ويتحقق من العضوية والبعد والتصنيف والإشارة والصلاحية والنطاق والدورة والمجموع، دون استيراد المولد أو المحرك. لا يقدم الأوراكل قرار قبول للمحاسب؛ كلمة `eligible` تعني صلاحية مصدر اصطناعي وفق العقد المقترح فقط.

يجب أن يحتوي كل دور مصدر سجلات فعلية، وأن يوجد حساب TB وبند مالي طرفي على الأقل؛ ملفات الترويسات وحدها أو العنوان وحده لا تثبت نطاقًا أو حقيقة مالية صفرية. سياسة الإشارة للفئات ثابتة: `debit-positive` للأصول و`credit-positive` للالتزامات وحقوق الملكية. يحتفظ المخصص المقابل للأصل بسياسة الأصل ومساهمته السالبة، ولا تقلب السياسة لإغلاق الفرق.

كل حقل يحمل SHA256 الأصل ورقم سجل CSV (الترويسة=1) والعمود والنص الخام. رقم سجل CSV ليس وعدًا برقم السطر المادي إذا احتوى ملف مستقبلي حقولًا متعددة الأسطر. تحفظ `inventory` جميع صفوف المصدر، حتى صفًا مرفوضًا ذا عرض أعمدة خاطئ. `facts` في نتيجة محجوبة أداة تشخيص للأوراكل، ولا تمنح سلطة مالية للمنتج.

السلبيات تثبت الأسباب، لا «عدم الانهيار»: ملكية خاطئة مع مبلغين متساويين، تصنيف خاطئ مع ميزان ومعادلة متوازنين، طفل بأبوين، دورة، أب غائب، صفر مفقود أو فارغ، مجموع تحكم خاطئ، دليل منتهي، خريطة منافسة لنفس الحساب/الأبعاد، حساب صفر غير مربوط، خريطة تستهدف أبًا، إشارة المخصص المعكوسة، كسور تحت وحدة العملة، نطاق أجنبي وصف مجهول متأخر. لا تُسقط المشكلة لتصنع تفردًا.

`verify_claim` واجهة اختبار مقترحة لمحول مستقبل، **ليست API للمنتج**. تختبر تسع حالات ادعاء محرف: تبديل أعضاء متساويين، تغيير الأب، الإحداثية أو البصمة أو النص، إسقاط الصفر أو صف مصدر، إحلال boolean محل صفر نقدي، وتحويل رفض إلى أهلية. تفشل جميعها بسبب assertion محدد حتى حين لا تتغير المجاميع.

## التجميد وإعادة الإنتاج

[INPUT-MANIFEST.json](INPUT-MANIFEST.json) يثبت 74 أصلًا: العقد، فهرس الحالات و72 مصدرًا. `run.py` لا يعيد إنتاج البصمات ولا يصحح expected. اختبار خاص يغير بايتات مصدر في مجلد مؤقت ويثبت فشل الحارس دون إعادة ختمه. يكشف حارس العضوية أيضًا الملفات الزائدة أو المفقودة ضمن المصادر المجمدة.

لإعادة إنتاج الأصول في مجلد منفصل، دون المساس بالمجمدة:

```sh
python3 -B audit/tb-financial-hierarchy/generate.py --output /tmp/fin1a-reproduction
```

اختبار إعادة الإنتاج يقارن كل البايتات والفهرس بالمجموعة المجمدة. لا تعتمد الحزمة على seed أو وقت النظام أو مسار جهاز. لا توجد آلية تلقائية لإعادة ختم المتوقع؛ أي تصحيح مالي لاحق يحتاج دليلًا ومراجعة مع حفظ تاريخ الفشل.

## مراجعة أداة القياس

كشف المراجع المستقل في النسخة الأولية قبول أربعة ملفات ترويسات بلا سجلات، وقبول قلب متسق لكل إشارات الخريطة والدليل وقيم البنود والمجاميع مع بقاء المعادلة متوازنة. هذان عيبان في الأوراكل المقترح؛ ليسا عيبين مثبتين في المنتج. أضيف شرط الحد الأدنى للأدلة وسياسة الإشارة واختبارات إعادة إنتاج الحالتين والعنوان وحده. نجحت 12 مجموعة بعد تصحيح الدليل والإشارة، ثم أضيفت مجموعة لحارس عضوية الملفات فأصبح الإجمالي 13؛ لم تتغير الحالات الـ18 أو المتوقع أو بايتات مصادر CSV. تحفظ [ملاحظات المراجعة](REVIEW-NOTES.ar.md) النتيجة الأولى وبصماتها وحدود التصحيح.

## ما يحتاجه تفعيل لاحق

راجع العقد والحقيقة والأوراكل مستقلًا، ثم احتفظ بعائلة/قصة تقييم جديدة لم تدخل ضبط القارئ. يأتي بعدها قارئ مستقل لعائلة FIN الهرمية، مع بقاء العقد المسطح الحالي دون تغيير. يجب أن يثبت كل سجل وعلاقة والد/طفل، ويجرد الرفض والمجموع والعنوان ولا يستنتج الهيكل من توازن المال. يشمل الإغلاق العامل والسياق والقرار والإلغاء والجلسة والاستعادة والتصدير المستقل والمساعد والواجهة AR/EN وسعة معلنة والبوابات القائمة.

XLSX والرؤوس المدمجة وPDF وOCR والفترات والعملات المتعددة واستنتاج السياسة والجهاز الضعيف والقياس الميداني خارج هذه الحزمة. نجاحها لا يغلق FIN-1 ولا يثبت اكتمال القوائم أو رأي تدقيق أو دقة عامة.
