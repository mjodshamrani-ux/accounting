# معايير قبول التنفيذ أو الامتناع

هذه شروط تنفيذ مستقبلية، وليست نتائج نجاح منتج. الحالة الحالية: عقد وعينات وأوراكل ومراجعة تحضيرية فقط. عيب ترتيب XLSX المفحوص في مرشح GL–TB عمل تشخيصي منفصل، ولا يثبت دعم XLSX لعائلة الأصول الطويلة.

1. اختيار `fixed-assets-long-components-gl-1` صريح لمصدر register فقط. اختيار العائلة الأفقية للسجل الطويل لا يؤدي إلى تخمين عائلة أو fallback. تبقى المصادر الثلاثة وعائلاتها ودلالاتها القديمة.
2. لكل `(scope, Asset ID, Asset dimensions)` أربع خلايا Amount مقدمة وأربعة أعضاء أصلية، لا صف مجمع مصطنع. تحفظ مواضع الأعمدة حتى عند إعادة ترتيبها، وتقبل الصفوف المتداخلة وغير المتجاورة دون اعتماد الترتيب كهوية.
3. الأربعة كاملة وفريدة. حذف صفر أو carrying أو depreciation مصدر ناقص يرفض ماليًا؛ التكرار مساويًا أو مختلفًا أو تالفًا يرفض، مع بقاء جميع الأعضاء الخام. لا اعتبار العدد أربعة كافيًا إذا كان نوع مكرر ونوع غائبًا.
4. Scope نفسه على جميع المصادر والصفوف. اختلاف التاريخ أو العملة أو الإصدار أو ledger يرفض؛ لا تقسيم صامت إلى نطاقات مقبولة. الهوية حرفية وValuation reference واحدة للأصل؛ لا دمج 001 و1 أو الأبعاد المختلفة.
5. لا قيمة مخمنة أو مشتقة بدل المقدم. تتحقق معادلة carrying بعد اكتمال الدليل. negative/signed zero/علامة موجبة/أس/آلاف/كسر زائد/مسافة في المال مرفوضة. حدود العملة والمبلغ والمجاميع موروثة، والفرق الموقع حتى 2×10^14 لا يقص.
6. خريطة وسياسة وأستاذ لكل مكون من الثلاثة بما فيه الصفر. carrying لا يخلق حسابًا رابعًا. يرفض التالف/التكرار، وتظل الروابط الناقصة/اليتيمة missing. لا يستنتج دليل صالح من تساوي الفرق أو الاسم.
7. كل مقارنة لحساب/أبعاد/مكون على حدة. حالتا net-equal وopposing-account تظلان difference. يظهر GL السالب بعلامته. حسابا كلفة متعاكسا الفرق لا يعتمد مجموعهما الصفري.
8. جرد وخلايا ومجموعة أعضاء كاملة عبر الأصول الأربعة؛ الأخطاء المتأخرة تبطل القبول الكامل. نقص من الأحداث أو نقل عضو لعائلة أخرى أو نطاق آخر يرفض. تصريح اكتمال الحسابات الحقيقي ومرجعه شرط منفصل عن سلامة الحساب.
9. تغيير الأصل/اختيار العائلة/النطاق/الخريطة/السياسة/التأكيد يبطل السياق والحدث والنتيجة والتصدير القديم. لا يعاد إحياء قبول بعد تغيير ثم إعادة الحالة دون حدث صحيح.
10. actual worker يطابق الطلب والسياق وبايتات الأصول والنتيجة المعاد حسابها؛ الرد الملغى أو المتأخر أو cache المزور يرفض. لا يكفي نجاح دالة متزامنة لإثبات العامل.
11. save/restore/export يعيد التحليل من البايتات الأربعة. تجربة فعلية كاملة مع قبول وundo ورفض وتغيير عائلة، وتصديران مباشر وبعد الاستعادة. الأرشيف الأفقي القديم ومخططه لا يتغيران بلا ضرورة مثبتة.
12. مدقق مستقل للتنزيل يعيد الأصول SHA/base64 ويقرأ CSV/Decimal وXML الخام، يعيد الأربعة وثلاثة أنواع مقارنات، ويثبت row/column/Component لكل Amount وكل عضو. computed-to-computed ليس دليلًا مستقلًا.
13. المصدر CSV فقط لهذه الدفعة. الامتدادات الأخرى والصيغ/الصور/PDF والعائلات المختلطة داخل register تمتنع. لا تغييرات عامة على قارئ XLSX بسبب نجاح فحص TB المنفصل.
14. حدود الفيزيائي: 8 MiB لكل أصل، 20000 صف عبر الأربعة شامل الفراغ، 100 عمود، 32767 UTF-16 لكل خلية؛ أحداث 1000 وأعضاء 20000/100000 وجلسة 64 MiB؛ يفحص الحد قبل النسخ/التوسيع. أدلة التصدير الإضافية تخضع لحد Excel قبل إنشاء الملف.
15. واجهة الأصول الحالية تعرض الأربعة وعضوية المصدر واختيار العائلة بنفس مكوناتها وتنسيقها، مع AR/EN و1440/390/320 ولوحة المفاتيح وحالات النقص والخطأ والتنزيل. النجاح البرمجي لا يثبت القبول البصري.
16. طفرات ذات معنى: حذف صفر، اختيار أول مكرر، إسقاط منافس تالف، تبديل component بين أصلين، دمج الأبعاد، حساب carrying المفقود، دمج فروق المكونات، قلب GL السالب، تجاوز صلاحية السياسة، إسقاط عضو، ثقة cache/حدث قديم/تنزيل قديم. لا يحسب خطأ syntax أو timeout اكتشافًا.
17. اختبارات مركزة ثم lint/types/units/build والخصوصية والطفرات والانحدار المناسبة على الشجرة النهائية، مراجعة مالية مستقلة، ومتصفح فعلي. بوابات CI/الرفع/الدمج/النشر تخضع لمسار التفويض والفحوص لاحقًا؛ ليست ضمن هذا التحضير.
18. ينشر التقرير الحالات الممتنعة وحدود الدعم صراحة. الأصول الاصطناعية لا تثبت تقييمًا ميدانيًا أو وفورات وقت أو اكتمال منصة، ولا تمنح صلاحية حساب استهلاك أو تقييم أو سياسة جديدة.

التوقف المالي الملزم: source-error أو missing أو difference أو دليل اكتمال غير مؤكد يمنع accept. يجوز عرض أدلة الخام والتشخيص ومراجعة الرفض الكاملة دون ادعاء اتساق مالي. لا يعالج النقص بقرار مستخدم يلغي دليل المصدر.
