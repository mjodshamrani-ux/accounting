# INV-1F-G4 دورة أصل PDF والقرارات

[العقد](contract.json) يضيف بروتوكولًا صريحًا للأصول الأربعة والنطاق والاكتمال والأحداث، دون تغيير الجلسة القديمة أو فتح امتداد في الواجهة. العامل يعيد القراءة من الأصول، والمتصل يعيد إثبات أن الرد يجيب عن الطلب الملتقط نفسه. تبقى نواة الحساب والرفض والأوراكل المجمدة دون تخفيف.

```sh
pnpm test:inventory-pdf:lifecycle
pnpm test:inventory-pdf:lifecycle-proof
pnpm test:inventory-pdf:lifecycle-mutations
pnpm build
pnpm exec playwright install chromium
pnpm test:inventory-pdf:worker-browser
```

تنتج الحزمة أدلة خاصة داخل work أو مجلد البيئة المحدد. لا ترفع results أو جلسات أو ملفات عمل حقيقية. ترجع لاختبار أساس INV-1F المختوم نفسه: 19 PDF و56 صفحة إجمالية وأربعة عروض موجبة وعائلتا تخطيط وقصة معروفة، وليست تدريبًا أو holdout جديدًا.

[مدقق الدورة](check_lifecycle.py) يفحص بايتات الأصول داخل الجلسات والنطاق وسياق كل قرار وأعضائه وتسلسل القبول والإلغاء والرفض وإعادة الفتح، ثم يستعمل مدقق G3 والأوراكل دون تعديلهما للمال والكمية والأبعاد والحروف وروابط الخريطة والسياسة وGL. يفحص المؤشر/الرد/الجلسة المتسقة لكن الأجنبية، ولا يكتفي بعدد القراءات. يجرب مشغل الدليل 16 تحريفًا دلاليًا مع إبقاء نسخ القيمة والجلسة والاستعادة متفقة حيث أمكن، ويقبل إعادة تنسيق JSON سليمة.

فحص Chromium يعمل على نص Worker المضمن في حزمة الإنتاج، لا worker بديل. يستخرج عبارة النص المحددة من chunk بعد البناء ويقرأها كقيمة string داخل VM فارغ ثم يشغل بايتاتها نفسها في Worker أصلي تحت سياسة CSP نفسها الموجودة في حزمة النشر. لا ينفذ مصدر المستند ولا يعتمد على حالة الواجهة أو يولد رسمًا بدل الحساب. هذه حاضنة backend داخل المتصفح؛ تفعيل PDF للمستخدم والتصدير خطوة G5 مستقلة.
